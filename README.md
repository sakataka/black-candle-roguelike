# Black Candle Roguelike

TypeScript + Vite + PixiJSで作っている自律遠征ローグライクです。プレイヤーは探索者を直接動かさず、灰灯院の観測者「灯守」として遠征団を送り出します。遠征前に作戦カードで探索者の判断の傾向を決め、動き続ける遠征を見ながら、敵の予告や探索者の言葉を手がかりに灯火で介入します。介入しなくても探索者は本人の判断で進みます。

目標は三つの層に分かれます。大目標は「黒燭への道」（第一の帰還路 → 真相を一つ → 三つの真相 → 黒燭核 → 結末）、遠征ごとの目標は支度で選ぶ任務一つです。遠征中は次の帰還路と「帰還なら+N / 倒れれば+M」の灯片の見込みを追います。成果はすべて灯片で表します。詳細は[目的と進捗の設計](docs/goals-and-progress-design.md)を参照してください。

## 遊びの流れ

支度画面と観戦画面の「遊び方」から、ルールの説明と、職業・装備・道具・敵・部屋と罠の図鑑を開けます。本文は `src/game/content/guide.ts`、図鑑と所持品の説明は `src/game/content/descriptions.ts` にあります。

1. **タイトルから灰灯院へ入る**: 「灯を掲げる」で支度画面を開く。「記録を選ぶ・新しく始める」から、最大5つの記録（灰灯院ごとの保存）を切り替えたり、新しく始めたりできる。灯片で施設（作戦室・書庫・灯火の祭壇）を強化し、療房で古参の古傷を癒やす。見出しの下に「黒燭への道」の次の目標が出る。探索者、今回の目標（任務。推奨が選ばれている）、作戦カード（初期2枠）を選び、画面下の出発ボタンで送り出す。
2. **観戦しながら灯を捧げる**: 探索者はAIで自律行動する。「閃灯（敵を怯ませる）」「癒灯（回復・浄化）」「導灯（周囲と罠を照らす）」「護灯（護りと押し戻し）」に加え、「置灯」で退路を照らし獣や亡者を誘い、「借灯」で未来の灯を借りられる。介入は探索者の手番を消費しない。危機には地図の下に「〇〇が灯を求めている」という押せる呼びかけが出る。灯火が満ちて溢れそうな時は使い道を勧める。
3. **動き続ける遠征へ伝言する**: 3階・6階の帰還判断や危機介入は地図に並ぶ期限つきの伝言。帰還判断には「帰還すれば確定するもの」と「進んで倒れた時に失うもの」が並ぶ。操作しなければ本人が任務に沿って解決する。第六階の先に帰還路はない。敵・探索・状態異常・灯芯の消耗は進み続け、一時停止はできない。詳細を開くと、その時点から続行の各案について12本の未来をWeb Workerで計算する。計算を待つ必要はなく、3階・6階では作戦カードも組み替えられる。
4. **結果を振り返る**: 今回の目標の達否、持ち帰った灯片の内訳、「黒燭への道」で進んだ章と次の目標を示す。HP推移・階層・判断・灯介入を1本の軌跡で振り返り、最も激しい被弾やHPが3割を切った瞬間などの転機と、次に効きそうな作戦・灯を示す。作戦はその場で次回に採用できる。
5. **遠征団が育つ**: 生還者は古参として残り位階が上がる（最大HP・攻撃が位階の上限まで伸びる）。瀕死で帰ると新たな古傷（判断や能力の悪い癖）を負い、倒れた者は戻らない。遠征団が満員の場合、志願者は生還しても加入せず、既存の古参を全員保持する。
6. **クリア後も続く**: 第十層を踏破すると次の燭階（5段）が開き、制約が重なる代わりに灯片が上乗せされる。結末を選ぶと周期が進み、継燭（残した探索者が「堕ちた灯守」として第十層に立つ）・消燭（闇と鋭い敵、灯片+25%）・分灯（灯火増・敵増）の余波が次の迷宮を変える。倒れた探索者は倒れた階に墓標を残し、後の遠征で弔うと遺品と灯火を受け継げる。

## 現状

- seedから名前・職業・気質を持つ候補者が生成され、支度を終えて出発するとAIが自動で遠征します。探索者の選択だけでは出発しません。通常UIには移動、アイテム使用の直接操作を出しません。
- 観戦画面は移動補間・カメラ追従・ダメージ数字・被弾フラッシュ・射撃の弾道・撃破演出を持ちます。吹き出しは気質・職業・古傷・古参・戦況・任務・灯への感謝に応じた150以上の台詞を使い、連続表示や同じ話題の繰り返しを抑えます。発話は戦闘乱数や進行速度を変えません。探索済みの記憶は減光して現在視界と区別します。
- 射手・術師・守り手は危険範囲と残り手数を予告し、発動後に隙を見せます。探索者AIも同じ可視情報で回避し、遮蔽・狭路・既知の罠を利用します。閃灯で構えを止め、護灯で押し戻して崩すこともできます。
- 任務の条件を満たすと灯火が1つ戻ります。殉職者の墓標には最後の3手の残響と教訓が残り、弔った探索者から後の遠征のAIへ受け継ぎます。
- 墓所では撃破の響きで亡者が覚醒し、炉心遺跡の通気口は予告後に敵味方へ熱を与え、黒燭中枢では灯の介入が守り手の構えを変えます。法則は観戦画面にも表示します。
- 借灯は一遠征一回、灯火が尽きてHPが減った時に使えます。回復・短い護り・灯火を得る代わりに、後で得る灯火を返済へ回します。未返済分は次の遠征の開始灯火からも返します。
- 敵が見えない移動は早送り（calm pacing）し、戦闘や被害のある手はゆっくり見せます。想定表示時間は1倍速で平均約4〜5分です（2026-10-03の比較条件）。到達階や行動によって変わります。
- 灯火は開始時3（祭壇で増加）・最大6で、階層を降りる・守り手を倒すと1つ戻ります。効果のない介入（怯ませられる敵がいない閃灯、HPが満タンで毒・出血もない時の癒灯）は受け付けません。
- 探索者AIの判断閾値（回復、交戦、寄り道、罠、遠隔対応、急ぎ始める手数）は `aiPolicy` にあり、基準値→気質→方針→作戦カード→古傷→継承した教訓の順に合成します。予告回避・地形評価は `realtime.ai` で調整します。
- 遠征開始時に「真相を持ち帰る」「黒燭核を討つ」「先人を弔う」（墓標がある時）「遺物台帳の補完」「灯路の先駆け」から任務を選びます。報酬の灯片は生還した時だけ受け取り、帰還路での探索者の既定の判断も任務に従います。
- 3階・6階の帰還判断と、4〜6階・7〜9階で各1回の危機判断があります。三つの真相が揃った状態で10階の番人を倒すと、結末の判断が加わります。発生する判断の数は遠征の経過によって変わり、出発後の伝言は操作しなくても本人が解決します。
- 4〜9階の文脈判断は、HP、状態異常、遠隔敵、所持品、経過ターンに応じた危機介入です。回復、護り、浄化、地図化、敵の押し戻し、金や最大HPの代償がその場でゲーム状態へ反映されます。
- 「慎重・探究・剛胆」の気質と「生還・探究・征圧」の方針がAI判断へ反映されます。本人の既定の判断を上書きしたり、一部の危機介入に使ったりする「啓示」は1遠征につき2回です。帰還の指示には使いません。
- 1倍速を基準に、0.5倍・1倍・2倍・3倍で観戦できます。伝言中もAIとラン内時計は動きます。進行中に灰灯院へ戻る操作は無効で、遠征の終了後に次の支度へ戻れます。
- 遠征の手数制限は「灯芯」です。1550手で警告し、1800手で尽きると未帰還になります。
- 得点は廃止し、成果は灯片で表します。到達・守り手・発見・弔いは倒れても半分残り、生還・持ち帰り・任務・新しい真相は生還時だけ受け取ります。結果画面に内訳を表示します。
- campaignはローカル保存し、保存形式version 4で三職業の真相、結末、任務、危機介入、最大100件の遠征録（灯片の内訳つき）、灯片、施設、遠征団、殉職者を保持します。最初の記録の保存キーは`black-candle-campaign-v1`で、追加の記録は別のキーを使います。教訓・借灯の未返済分・最後の判断・鍛錬と覚醒の累計は省略可能な追加項目です。旧version 1〜3は読み込み時に移行し、旧記録の得点は捨てて獲得灯片の合計だけを残します。
- 職業ごとに初めて第十層を踏破すると、その職業ゆかりの「継承品」が解放され、以後はどの職業でも一つ持ち込めます（支度画面の「IV 継承品」）。全職業の踏破を条件にはしていません。
- 遠征をまたぐ強化には古参の位階、施設、全探索者に継承される灰灯院の鍛錬があります。古参は倒れると失われるため、送り出すかどうかも判断になります。鍛錬は獲得した灯片の累計に応じて上がり、灯片を使っても減りません。
- 支度画面には「黒燭への道」（5章）と遠征録（最高到達階、最多灯片、踏破回数、達成任務）を表示します。結果画面では前回との深度・灯片の比較と、新記録や新しい真相・結末を表示します。
- ゲーム状態とルールは `src/game/core/` にあります。
- AI は `src/game/ai/`、表示は `src/game/renderer/`、コンテンツ定義は `src/game/content/` に分けています。
- 階層は1-3Fの黒石迷宮、4-6Fの墓所、7-9Fの炉心遺跡、10Fの黒燭中枢に分かれ、領域ごとに地形画像と出現傾向が変わります。
- マップ生成は単なるランダム配置ではなく、開始圏、寄り道/報酬圏、危険圏、出口圏を持つ配置プランで、敵・報酬・イベント・罠の置き場所に意図を持たせています。
- 生成AIで作った遮蔽地形が各バイオームに配置されます。遮蔽は歩行可能ですが視線と遠隔攻撃の射線を遮るため、遠隔敵への対策として使えます。
- 針の罠、毒霧の罠、崩れる床が配置され、発見済みの罠はAIが避けます。罠は敵にも発動します。
- 罠は必ず発動するわけではなく、基本回避率と装備・職業特性による補正で回避判定があります。回避率の下限/上限もJSONで調整できます。
- 遠隔敵や術師は近づかれると間合いを取り直し、ウォーロックは灰の小型敵を呼びます。大ヒルは噛みつくと少し回復します。
- 敵は数値だけでなく振る舞いで区別します。倍速（2回動くが噛みつくのは1回）、群れ（仲間が隣にいると強い）、盾持ち（鈍器か隙でないと通りにくい）、蘇る骨（鈍器か浄化で砕く）、盗人、癒し手、装備を錆びさせる敵、分裂、爆ぜる敵、再生、待ち伏せ、突進の予告があります。一部の敵は眠っていて、忍び寄れば不意打ちできます。設定は `monsterBehaviors`。
- 各階に入ると、確率で「階の兆し」（濃霧、群れの気配、飢えた階、宝の匂い、静寂、血の月、眠りの階、古戦場）が一つ引かれます。2階以降には銘を冠した精鋭（金の輪）が潜み、倒すと印つきの装備を落とします。
- 封印の間、亡者の食堂、宝物庫、燭台の回廊、納骨部屋、炉心室は、踏むと周辺に敵・報酬・罠・遮蔽を展開する小部屋イベントです。部屋名ごとに「待ち伏せ」「亡者と物資」「遮蔽越しの守り手」など役割が違います。
- 呪いの祭壇、炉の制御石、封印の鍵は階層をまたぐ小目的イベントです。祭壇は代償つきで隠れ罠を一部暴き、制御碑は7F以降の通常敵を弱め、封印の鍵は次のボス報酬を増やします。
- 旅商人では、商人マスに着いた探索者AIが回復、解毒・止血、装備購入、地図購入から状況に応じてサービスを選びます。今取引できるものを `GameObservation.merchantServices` で受け取り、`merchantService` action で購入します。
- 謎の小瓶と謎のお札は、使うまで効果が読みにくい不安定アイテムです。回復や護りになることもあれば、毒・出血などの反動もあります。プリーストは危うい祈祷札や小瓶を比較的安全に扱えます。
- 3F、6F、10Fには守り手が出現し、倒すまで下り階段が封じられます。守り手は階ごとの候補から遠征ごとに選ばれ（3階は墓所の司祭・甲殻虫の女王・ジャイアントワーム、6階は黒石の巨像・デスナイト、10階は黒燭の番人・シャドウデーモン）、手下の呼び出しや怒りを持ちます。6階の守り手を倒して生還すると職業固有の真相を記録でき、三つ揃えた状態で10階の番人を倒すと「継燭・消燭・分灯」の結末を選べます。
- 開始職は、ナイト、レンジャー、プリースト、トレジャーハンター、アルケミスト、ウォーリア、シーフの7職から選べます。職業ごとに初期HP、攻撃、防御とレベルごとの伸び、初期装備、得意な武器の型、固有技（誓いの一撃・足止め射撃・聖なる光・看破・毒の瓶・突進・影渡り）、職業特性、1遠征内で完結する小さな固有目的があります。支度画面で職業と初期能力を比較でき、観戦中は遠征帳で現在の能力・任務・方針・装備・記録を確認できます。職業特性は下の「職業別の小目的」を参照してください。
- 拡張v1は黒石鉱脈・浸水書庫・茨の礼拝堂の寄り道部屋、敵12種、装備・道具12種を追加します。解錠箱・文献・祭具の報酬をAIも扱い、未探索の地形や視界外の敵を判断に使いません。弓の射撃、両手武器と盾の排他、指輪1枠、抗毒・反射・探索・再生効果を持ちます。29シート・137セルを登録し、既存の携行品・罠・イベントも個別画像になりました。実装順・調整結果・残る範囲は [拡張v1の実装記録](docs/art-expansion/implementation-plan.md) にあります。
- 誓約の残響、レンジャーの道しるべ、灯火の泉は職業専用イベントです。該当職なら報酬や探索補助が強くなり、非該当職でも小さな効果だけ得られます。
- 武器には型があります。剣は隙への追撃と返し斬り、槍は2マス先への突きと貫通、斧はなぎ払い、短剣は2回刺しと不意打ち、鈍器は防御無視と揺らし、弓は射撃。装備には修正値（+N）と印（吸・会・浄・砕・毒・棘・癒など17種）が付き、同じ品を拾うと鍛え直して強くなります。装備の置き場所は決め打ちせず、格と部位から抽選します。探索者AIは持っている武器で戦い方を変え、弓と近接武器を状況で持ち替えます。詳しくは [ブラッシュアップ提案と実装記録](docs/brushup-proposal.md)。
- 装備は修正値と印のほかに、遠隔防御、罠回避補正、罠回避ペナルティ、特定ファミリーへの追加ダメージを持てます。罠よけのマントは罠回避、タワーシールドは遠隔対策、シルバーメイスは不死・悪魔対策に寄せています。
- チューニング用の主要パラメーターは `public/config/game-balance.json` にあります。dev server起動中でもJSONを編集してブラウザをリロードすれば、再ビルドなしで反映できます。
- 新しい敵・アイテム・武器・イベントは、PNGスプライトシートを `public/assets/sprites/` に置き、`src/game/content/assets.ts` で切り出します。
- NetHack由来の参照データは設計seedとしてのみ扱い、現行実装はTypeScript製の独自ゲームとして進めます。
- 旧 Tauri / xterm / NetHack bridge 実装はリポジトリから削除済みです。

## 起動

```sh
bun install
localweb dev black-candle
```

ポートはLocalWebが割り当てます。確認先は以下です。

```text
http://black-candle-dev.localhost/
```

## 設定ファイル

ゲームバランスは `public/config/game-balance.json` で編集します。主な項目は以下です。

- `rules`: マップサイズ、視界、最大階層、所持枠、経験値テーブル、レベルアップ、敵/アイテム/罠/遮蔽の出現数、敵の階層補正（`monsterHpScale` / `monsterAttackPerFloor`）、遠隔敵が退いた後の間隔、罠回避率、状態異常ダメージ、観測ターン上限など
- `aiPolicy`: 探索者AIの判断閾値の基準値と、気質・方針ごとの上書き
- `tactics`: 作戦カードの枠数と定義（AI閾値の上書き・加算、開始時の携行品、小さな能力補正、書庫で解放するまでの封印）
- `scars`: 古参が瀕死で帰還した時に負う古傷（作戦カードと同じ形）
- `campaign`: 灯片の獲得量、古参の位階ボーナス、古傷の条件、遠征団の上限、療房の費用、施設の費用と効果、鍛錬と守り手の覚醒（`journey`）
- `lantern`: 灯火の開始数・上限・回復量、4種の介入の費用と効果、batch用の灯守AIの介入閾値
- `ascension`: 燭階ごとの制約（ルール値への加算、灯火の増減）と灯片の上乗せ率
- `aftermath`: 結末ごとの周期の余波（ルール値への加算、灯火の増減、第十層のボス差し替え、灯片の上乗せ率）
- `campaign.shards` / `campaign.missionShards`: 遠征の灯片の内訳と、任務ごとの報酬
- `autonomous`: 啓示回数、先読みの本数、観戦速度の基準時間（calm / traversal / exploration / danger）
- `realtime`: 伝言の期限、敵ごとの予告・隙・倍率、地形AIの評価、置灯・借灯、階層法則、任務（弔いの寄り道・達成時の灯火）、教訓、台詞の間隔。詳細は [リアルタイム遠征の設計](docs/realtime-expedition-design.md)
- `roles`: 開始職の素の能力と伸び（`growth`）、初期インベントリ、得意武器・固有技などの職業特性、画面表示用の特徴説明
- `weaponTypes`, `seals`, `equipmentRolls`, `guaranteedEquipment`: 武器の型、印、修正値と印の抽選、階ごとに必ず置く装備の枠
- `skills`, `monsterBehaviors`, `omens`, `elites`, `bossFloorScaling`: 固有技、敵の振る舞い、階の兆し、精鋭の銘、守り手の階ごとの倍率
- `legacies`: 職業ごとの踏破で解放される継承品
- `monsterStats`: 敵ごとの HP、攻撃、防御、階層補正
- `monsterSpawnRules`, `itemPools`, `guaranteedItems`, `eventPools`, `trapPools`, `bosses`: 階層・バイオームごとの出現設定
- `equipment`, `consumables`, `events`, `merchantOffers`, `trapEffects`: 武器/防具の値、遠隔防御、罠回避補正、消耗品効果、イベント報酬、小目的フラグ、商人価格、罠効果

`src/game/content/entities.ts` は表示名と、AI・戦闘・灯片で使う最小限の分類値だけを持つコンテンツ辞書です。数値調整は基本的に JSON 側で行い、画像の切り出しは `src/game/content/assets.ts`、生成方針は `AGENTS.md` と `docs/` に集約します。

## AIシミュレーション

```sh
bun run simulate:ai 20260504 1600 role.oathbound --decision-policy temperament
bun run simulate:ai 20260504 1600 role.ash-scout --decision-policy always-continue
bun run simulate:ai 20260504 1600 role.lantern-priest --decision-policy return-6
```

`--decision-policy` は `temperament`、`always-continue`、`return-3`、`return-6` を指定できます。AIやcoreを触った場合は、拾得、アイテム使用、戦闘、階層移動、選択解決が発生することを確認します。

## バランス調整PDCA

複数seed、複数職業、複数configを同じ条件で回すには batch simulation を使います。集計には任務達成率、危機介入、予告発生・回避、敵の罠発動、亡者覚醒、熱の被害、置灯・借灯、未返済灯火も含まれます。探索停滞の連続計測は階層移動でリセットします。

```sh
bun run simulate:batch -- --preset smoke
bun run simulate:batch -- --preset standard --decision-policy temperament
bun run simulate:batch -- --preset standard --decision-policy always-continue --profile
bun run simulate:batch -- --preset compare --config baseline=public/config/game-balance.json --config scout-buff=tmp/balance/scout-buff.json --out tmp/sim-reports/scout-buff.json
bun run simulate:batch -- --preset deep --seeds 20260504 --roles role.ash-scout
bun run simulate:batch -- --seeds 20260504:20260533 --turns 1800 --roles all --watcher lantern
bun run simulate:batch -- --seeds 20260504:20260533 --turns 1800 --roles all --tactics tactic.archer-hunt,tactic.straight-path
```

出力は `tmp/sim-reports/*.json` と `tmp/sim-reports/*.md` に保存され、毎回 `tmp/sim-reports/latest.json` と `tmp/sim-reports/latest.md` も更新されます。`tmp/` はGit管理外です。職業別・気質別の勝敗、帰還・未帰還、灯片の中央値、発見、拾得、100ターン当たりの戦闘、方針選択分布、想定表示時間を比較できます。

`--heat N` は燭階、`--aftermath inherit-flame|extinguish-flame|divide-flame` は周期の余波を指定します。燭階や余波の難易度は、同じseed集合で比較してください。

`--watcher lantern` は人間の灯介入を模した灯守AIを有効にします。既存4種の閾値は `lantern.watcher`、置灯は `realtime.light`、借灯は `realtime.loan` にあります。`--tactics` は作戦カードを、`--legacy role.xxx` は持ち込む継承品を指定します。新ルールでの `temperament` は期限内を見守って本人に任せ、他の判断方針は比較用に選択肢を即時解決します。古いconfigに `realtime` がなければ従来ルールとして比較できます。

任務統合・鍛錬追加前の2026-10-03の確認（seed `20260504:20260533` × 3職業、1600手、気質判断、作戦なし、燭階0・余波なし）では、新ルールの介入なしは踏破40・帰還27・死亡21・継続中2、灯守AIありは踏破53・帰還28・死亡7・継続中2でした。未帰還はどちらも0件。置灯55回・借灯8回が発生しました。介入なしの継続中2件は1633手・1666手で踏破。当時の想定表示時間は旧ルール平均4.23分から新ルール4.40分へ増えました。停止や入力待ちはなく、回避行動や生存率の変化を含む値です。条件と残る課題は [検証記録](docs/realtime-expedition-design.md#2026-10-03の比較結果) にあります。

presetは用途で使い分けます。`smoke`は機能追加直後の短時間確認、`standard`は完了前の標準確認、`compare`はbaseline/candidateの同一seed比較、`deep`は問題seedの長ターン再現と`--trace` / `--profile`付きの詳細確認です。通常のbatchは`--log-limit 40`で直近40手のログと全体の集計値を保持します。遠征全体のログが必要な時は`--log-limit none`を指定します。CPU負荷を下げたい時は`--jobs 4`、単純な再現確認では`--jobs 1`を指定します。

基本の流れは以下のとおりです。

1. 変更前のbaselineを保存する。
2. `public/config/game-balance.json` をコピーして候補configを作る。
3. 同じseed集合と職業集合で `simulate:batch -- --preset compare` を実行する。
4. Markdown summary の `PDCA Alerts` と `Top Run Regressions` から悪化seedを見る。
5. AIの判断ミスが目立つなら `src/game/ai/autoplay.ts`、数値の偏りなら `public/config/game-balance.json` を直す。

## 操作

- タイトル: 「灯を掲げる」をクリック、またはEnterなどのキーで灰灯院へ入る
- 灰灯院: 施設カードで強化、療房のボタンで古傷を癒やす、作戦カードをクリックで選択（枠数まで）
- 古参・志願者カードをクリックまたは `1`〜`4`: 探索者を選ぶ。画面下の出発ボタン（または選択済み探索者カードでEnter）で自律遠征を開始する
- `Q` 閃灯 / `W` 癒灯 / `E` 導灯 / `R` 護灯（または灯火バーのボタン）: 灯を捧げて介入する。黒燭が揺れている時は効きそうな灯が光る
- `T` 置灯 / `F` 借灯（または灯火バーのボタン）: 探索者の時計を止めずに追加介入
- 選択カードをクリックまたは`1`〜`4`: 本人の判断に任せる、帰還させる、啓示で方針を上書きする。3階・6階では作戦カードも組み替えられる
- `0.5×` / `1×` / `2×` / `3×`: 観測速度を変更
- 伝言は期限を過ぎると本人が解決。長期の先読みは詳細から開く。Spaceによる一時停止はありません
- 結果画面の `灰灯院へ戻り、次の遠征を支度する`: 次のseedの支度画面へ戻る

移動（斜めを含む8方向）、戦闘、拾得、装備、アイテム使用、商人利用、階層移動はすべてAIが人間と同じ `GameAction` で行います。灯守の介入も `invokeLantern` / `placeLantern` / `borrowFlame` / `resolveDecision` という `GameAction` です。再現用の状態投入・直接操作は開発ビルドのdebug bridgeに限定しています。

## 職業別の小目的

- ナイト: HPと攻撃が高い標準職です。ボス/守り手を倒すたび、足元付近に追加報酬が落ちます。
- レンジャー: 地図利用と遠隔圧への対応が得意です。地図系アイテムや地図購入を使うたび、追加探索と投げ針補充が起きます。職業特性として罠回避と遠隔防御も少し高めです。
- プリースト: 状態異常対策と防御的な粘りが特徴です。祭壇や浄化系の回復を使うたび、毒・出血を払い、短い護りを得ます。
- トレジャーハンター: つるはしと解錠道具を持ち、新しい寄り道部屋に入ると周囲の構造を記録します。真相はレンジャー系へ接続します。
- アルケミスト: 回復薬の効率が高く、解毒・治療後に少し追加回復します。真相はプリースト系へ接続します。
- ウォーリア: ハンドアックスとチェインメイルで出発し、守り手撃破の追加報酬を持ちます。真相はナイト系へ接続します。
- シーフ: 罠回避に優れ、解錠道具を消費せず箱を開けて追加の金を得ます。真相はレンジャー系へ接続します。
- 職業専用イベント: 誓約の残響はナイトへ備蓄を残し、レンジャーの道しるべはレンジャーへ投げ針と小地図を補充し、灯火の泉はプリーストの状態異常を護りへ変えます。

## 地形と戦術

- 遮蔽地形は `cover` タイルとして扱われます。歩いて進入できますが、FOV と遠隔攻撃の射線を遮ります。
- 遮蔽数は `rules.coverCountBase`, `coverCountFloorDivisor`, `coverCountMax` で調整します。
- 遮蔽画像は `public/assets/sprites/dungeon-cover-overlays.png` にあり、4テーマを `assetCatalog` の `sheet` 情報で切り出します。置灯・借灯・残響・通気口は生成AIの `realtime-rites-sheet.png` を使います。
- 敵・報酬・イベント・罠は `src/game/core/game.ts` の floor plan によって、開始圏、寄り道/報酬圏、危険圏、出口圏へ寄せて配置されます。
