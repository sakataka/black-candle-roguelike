# 目的と進捗の設計

2026-10-04。遠征の機能が増えて、何を目指していて今どこまで来たのかが見えにくくなっていた。目的を三つの層に分け、各層の目標を一つに絞った。保存データの互換性より分かりやすさを優先している。

## 見直す前の問題

- 遠征中に追う目標が並立していた。任務、誓い、方針、職業目的、真相、第十層の踏破があり、互いに衝突していた。慎重な探索者は誓い（第六階で帰還）を優先して、任務（第十層への到達）を落とすことがあった。
- 画面でいちばん大きく見える「暫定得点」には使い道がなかった。実際の通貨である灯片は、内訳も見込みも表示されていなかった。
- 帰還判断で、帰ると何が確定し、進んで倒れると何を失うのかが分からなかった。
- 「灯路」という言葉が五つの意味で使われていた。手数制限、第三階の判断、任務名、節目名、危機イベントである。
- 支度画面では、物語6段・真相3つ・燭階・周期・自己ベストが、一本の道筋にまとまらずに並んでいた。

## 三つの層

| 層 | 目標 | どこに出すか |
| --- | --- | --- |
| 大目標 | 「黒燭への道」の5章（第一の帰還路 → 真相を一つ → 三つの真相 → 黒燭核 → 結末） | 支度画面の見出しの下（次の章とヒント）、側欄、結果画面 |
| 今回の目標 | 支度で選ぶ任務を一つ | 観戦の側欄、帰還判断、結果画面 |
| いま | 次の節目（次の帰還路、または帰還路なし）と、灯片の見込み | 上部の道のり、側欄、灯片の見込み |

### 黒燭への道

`campaignProgress().roadmap` で章を判定し、最初に終わっていない章を `nextChapter` として返す。真相の章では、職業ごとに未回収の真相を示す。志願者カードには、まだ真相を持ち帰っていない職業に「真相を持ち帰れる」と表示する。

### 任務（今回の目標）

誓いは廃止して任務へ統合した。任務は次の五つ。「先人を弔う」は、迷宮に墓標がある時だけ選べる。

| 任務 | 条件 | 生還時の灯片 |
| --- | --- | ---: |
| 真相を持ち帰る | 第六階の守り手を倒し、生きて帰る | 6 |
| 黒燭核を討つ | 第十層の番人を倒す | 10 |
| 先人を弔う | 墓標を弔い、生きて帰る | 5 |
| 遺物台帳の補完 | 発見を6種記録し、生きて帰る | 5 |
| 灯路の先駆け | 700手以内に第六階へ到達し、生きて帰る | 5 |

- 条件を満たした時点で灯火+1を得る（`realtime.missions.rewardEmbers`）。灯片の報酬は生還した時にだけ受け取る。
- 帰還路での探索者の既定の判断は任務に従う（`missionWantsReturn`）。任務を果たしていれば帰り、果たしていなければ進む。「黒燭核を討つ」は常に進む。本人の意思に反して進ませる場合は啓示を使う。帰還させるのは常に無償。
- 支度画面では、灰灯院の状況と探索者から推奨の任務を選んでおく（`recommendedMission`）。その職業の真相が未回収なら「真相を持ち帰る」、墓標があれば「先人を弔う」、それ以外は「黒燭核を討つ」。
- batch では、任務の既定を気質から決める（慎重→真相、探究→台帳、剛胆→黒燭核）。

### 灯片への一本化

得点は廃止した。遠征の成果はすべて灯片（`calculateShards`）で表す。

| 内訳 | 量 | 倒れた場合 |
| --- | --- | --- |
| 到達 | 1/階 | 50%残る |
| 守り手 | 2/体 | 50%残る |
| 発見 | 2種につき1 | 50%残る |
| 弔い | 2/墓標 | 50%残る |
| 生還 | 帰還3・踏破6 | なし |
| 持ち帰り | 所持金と所持品の価値100ごとに1（上限4） | なし |
| 任務 | 上の表 | なし |
| 真相 | 新しい真相なら5 | なし |

燭階と周期の余波による上乗せは合計にかかる。値は `campaign.shards` と `campaign.missionShards` で調整する。観戦中は上部に「帰還なら +N / 倒れれば +M」（`shardForecast`）を常に出す。

### 帰還判断の得失

第三階と第六階の帰還路では、選択肢の上に二つの欄を出す。

- 帰還すれば: 灯片、古参の位階または遠征団への加入、真相の記録、任務の達否、古傷の恐れ
- 進めば: 狙えるもの、次の帰還路（第六階の先には帰還路がないこと）、倒れた時に残る灯片と失うもの

### 第十層

三つの真相が揃っていれば、番人を倒した後に結末を選ぶ。揃っていなければ問いを挟まずに踏破で終わる。以前の「研究へ封じる／戦果として持ち帰る」は効果に差がなかったため削除した。

### 用語

- 灯路: 灰灯院へ戻る道。第三階・第六階の帰還路、任務名「灯路の先駆け」、危機イベント「途切れかけた灯路」で使う。
- 灯芯: 遠征の手数制限。尽きると未帰還になる。
- 道中記: 観戦中のログ。遠征録（支度画面の過去の記録）と区別する。

## 灯守の役割（灯火の使いどき）

2026-10-04 に追加。目的を整理した後も、灯火は満タンのまま使われないことが多かった。30 seed × 三職業の batch では、介入なしの遠征で1回あたり平均6.9個の灯火が上限を超えて消えていた。灯守AIは平均9.8回介入し、溢れは0.6個、死亡は18人から8人に減った。介入の効果はあるのに、人間にはいつ使えばよいかが見えていなかった。

- **呼びかけ**: 灯守AIと同じ判断（`suggestLanternAction`）に理由を添え、地図の下端に押せる札として出す。危機（`crisis`）は「〇〇が灯を求めている — 2体に囲まれている ・ [Q] 閃灯」。札を押すか、キーを押すとそのまま捧げる。敵が一歩動くたびに点滅しないよう1.6秒保持し、その介入が効かなくなったら消す。
- **使いどき**: 灯火が満ちていて、敵が見えず階段も見つかっていない時は、静かな札（`spare`）で導灯を勧める。灯火欄の器を光らせ、「これ以上は溢れて消える」と書く。灯守AIの判断は従来のまま変えていない（batch の比較を保つため）。
- **溢れの計上**: 灯火の獲得は `gainEmbers` にまとめた。上限を超えた分は `lantern.overflowed` に数え、ログに「溢れて消えた」と残す。
- **手応え**: 捧げた直後に効果（「敵2体が3手のあいだ怯んだ」など）を地図の上に出す。結果画面には介入回数・溢れた灯火・残った灯火を出す。2つ以上溢れた遠征では、振り返りの示唆に導灯を出す。
- batch の Realtime Dynamics 表に `Rites`（介入回数）と `Overflowed Embers`（溢れた灯火）を追加した。

## 進捗を見せる器

支度画面の上部と結果画面では、文章を読む前に進みが分かるように三つの器を並べる。

- **黒燭**: 達成した章の分だけ下から満ち、五つの刻印が灯る。横の三つのくぼみは職業ごとの真相で、未回収と回収済みを形と文字で区別する。今回回収した真相や達成した章は結果画面で光る。結末まで記録すると炎が灯る。
- **鍛錬の器**: 灰灯院のLv、全探索者への命火・攻撃の加算、次のLvまでの灯片を出す。結果画面には今回の灯片とLv上昇を反映する。累計のため、施設で灯片を使っても減らない。
- **覚醒への道**: 守り手の肖像、区間内の踏破を表す印、未到達・挑戦中・突破済みを並べる。必要踏破数は設定値から読み、通常の踏破と覚醒突破を区別する。

観戦の上部には今回の任務の印と鍛錬Lvを小さく出す。任務条件を満たした印と、生還して報酬が確定した最後の印は分ける。第十階へ着いただけでは、番人撃破の印は灯らない。詳しい進め方と章の達成条件は折りたたみで読める。

表示は既存の `campaignProgress`・`journeyProgress`・`missionProgress` を使い、収集条件、戦闘、AI、保存形式は変更しない。実装は `src/ui/progress.ts`。

## 記録（保存スロット）

タイトルの「記録を選ぶ・新しく始める」から、最大5つの記録を切り替えられる。記録ごとに灰灯院（灯片・施設・遠征団・真相・周期・墓標）と作戦の記憶が別になる。

- 一覧には周期、黒燭への道の進み（5つの印と次の章）、遠征数、最深、灯片、遠征団の人数、最後に遊んだ日を出す。
- 切り替えと新規作成はページを読み直し、タイトルを飛ばして支度画面へ入る。支度画面の見出しにも使用中の記録名と「記録を切り替える」を置く。
- 消せるのは使用中でない記録だけで、「消す」→「本当に消す」の二段階にしている。
- 一覧は `black-candle-saves` に保存する。最初の記録は従来の保存キー（`black-candle-campaign-v1`・`black-candle-tactics`）をそのまま使うため、以前の遊びはそのまま「記録一」になる。実装は `src/ui/saves.ts`。

## 保存形式

campaign は version 4。version 3 以前の記録は、灯片の合計（`shardsEarned`）を引き継ぎ、得点は捨てる。旧任務（守り手の誓約）は未達として読み込む。施設・遠征団・真相・墓標・周期はそのまま保持する。
