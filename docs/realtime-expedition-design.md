# 動き続ける遠征の設計

2026-10-03。灯守は遠征を眺め、ここぞという瞬間に介入する。探索者の移動・戦闘・判断は自律的に進み、灯守の入力を攻略条件にしない。敵や装備の追加量ではなく、既存の戦闘・地形・人格・遠征団の記憶に判断の余地を増やした。

## 9つの機能

| 機能 | 実装と判断の手がかり |
| --- | --- |
| 1. 状況に合う吹き出し | 気質別の台詞に職業・古傷・古参・灯火不足・誓い・回避・隙・墓標・灯への感謝を重ねる。台詞選択は戦闘乱数を使わない。表示時間と再発話間隔を制限する |
| 2. 意図と助けを求める声 | 探索者が命火の低下や挟撃を言葉で知らせる。見守るだけでもAIは回復・回避を判断する。節目の伝言は期限を過ぎると本人が解決する |
| 3. 敵の予告と隙 | 虚ろ弓の亡者は射線、黒石の巨像は薙ぎ払い、術師と番人は呪印を予告する。危険範囲と残り手数を表示し、発動後は緑の輪で隙を示す。回避・閃灯・護灯で対応できる |
| 4. 地形を使う戦闘 | AIは可視の予告・既知の遮蔽・狭路・罠を評価する。自分は罠を避け、敵を罠へ誘う足運びを選べる。人間とAIの情報源は同じ `GameObservation` |
| 5. 置灯 | 一押しで直近の退路に灯を残す。壁に遮られる小さな視界を持ち、近くの獣・亡者を引き寄せる。ボスは誘われず、敵が灯へ到達すると消える。灯火と設置上限で連打を制限する |
| 6. 探索者の誓い（2026-10-04に任務へ統合。[目的と進捗の設計](goals-and-progress-design.md)） | 墓標があれば先人を弔う。慎重な者は第六階の真相を持ち帰る。他の者は守り手を越える。墓標への寄り道や第六階の帰還判断に反映し、達成すると灯火を得る |
| 7. 階層の法則 | 黒石は遮蔽、墓所は撃破による亡者の覚醒、炉心は予告つきの熱、黒燭中枢は灯による構えの変更。炉の熱は敵にも作用する。法則を灯火欄に表示する |
| 8. 殉職者の最後の判断 | 最後の3手と命火、敗因に応じた教訓を墓標へ残す。弔うと残響を読み、射線への警戒・罠への慎重さ・早めの回復を受け継ぐ。遠征後は教訓をcampaignへ保存する |
| 9. 未来から借りる灯 | 灯火が尽き、命火が減った時に一遠征一回使える。回復・護り・灯火を得る。後の階層・守り手・墓標・誓いの灯火で返済し、未返済分は次の遠征の開始灯火へ持ち越す |

## テンポと操作

遠征中は一時停止も灰灯院へ戻る操作もできない。速度は0.5・1・2・3倍。静かな移動を早送りし、予告へ反応する戦闘時間を確保する。ブラウザのバックグラウンド制限やOSによる休止を補正して擬似的に手数を増やす処理は追加していない。

灯の介入と伝言の選択は即時処理で、探索者の手番を消費しない。灯を何回捧げても、予告・伝言・置灯の寿命・状態異常の時計は延びない。通常行動がそれぞれの時計を進める。灯火・啓示・一回限りの借灯が介入の代償となる。

伝言は地図に並ぶ小さな欄へ表示する。スマートフォンでは固定の灯火欄の上へ置き、両方のボタンを操作できる。選択肢の登場を遅らせる演出は使わない。操作しなければ気質と誓いに沿った選択を解決する。守り手撃破で帰還路が開くため、帰還指示のためだけに階段まで歩く必要はない。続行時はAIが階段まで進む。

長期の先読みは詳細を開いた時だけWorkerで計算する。結果はその伝言を開いた時点の状態に基づく推定で、動き続ける現在の命火を保証しない。計算の完了を入力条件にせず、伝言が消えたらWorkerを停止する。直近の一撃は地図の危険範囲と手数を優先して判断する。

`Q` 閃灯、`W` 癒灯、`E` 導灯、`R` 護灯、`T` 置灯、`F` 借灯。伝言は番号キーまたはクリック。借灯の詳細はボタンの説明、未返済分は灯火欄の下と次の支度画面に表示する。

## 設定とPDCA

正本は `public/config/game-balance.json`。新しい値は `realtime` にまとめた。

| 設定 | 調整対象 |
| --- | --- |
| `enabled` | 新ルールの有効化。項目のない旧configは従来ルールとして比較可能 |
| `decisionTurns` | checkpoint・context・finalごとの伝言期限。単位は通常行動の手数 |
| `telegraphs.<monsterId>` | kind、windup、cooldown、recovery、range、damageScale。windup・recoveryは1以上を基本にする |
| `ai` | 回避する命火比率、地形移動を使う命火比率・間隔、遮蔽・敵・罠誘導の評価、隙への追加ダメージ、教訓の回復補正・罠への忍耐 |
| `light` | 費用、持続手数、視界半径、誘引距離、設置上限、灯守AIが残す灯火と介入対象数 |
| `loan` | 回復率、護り手数、借入灯火、返済灯火、灯守AIの使用命火比率 |
| `laws` | 墓所の覚醒間隔・階層上限・距離・攻撃補正、炉の周期・予告・燃焼手数・ダメージ・通気口数 |
| `missions` | 弔いの任務で墓標へ寄り道する最低命火比率、任務の条件を満たした時の灯火（旧 `vows`） |
| `dialogue` | 最低発話間隔（手数・実時間ms）、同じ話題の間隔、吹き出しの表示ms |

職業・敵・装備・生成・pacing・通常AIは既存の設定を使う。表示上の法則と灯の説明も設定値から作る。台詞本文は `src/game/content/speech.ts`、発話条件は `src/game/ai/speech.ts`。

候補は `tmp/balance/` へコピーし、同じseed・職業・判断方針・手数で比較する。値は正の周期・手数、0〜1の比率、妥当な非負コストを前提にする。JSON全体の数値検証UIは今回追加していない。

```sh
cp public/config/game-balance.json tmp/balance/candidate.json
# candidateのrealtimeを変更する
bun run simulate:batch -- --seeds 20260504:20260533 --turns 1600 --roles all --jobs 4 --config baseline=public/config/game-balance.json --config candidate=tmp/balance/candidate.json --out tmp/sim-reports/realtime-compare.json
bun run simulate:batch -- --seeds 20260504:20260533 --turns 1600 --roles all --jobs 4 --watcher lantern --label realtime-watcher
```

`temperament` は伝言を期限まで見守る通常の観戦条件。`always-continue`・`return-3`・`return-6` は判断を即時解決して経路戦略を比較する条件。灯守AIなし／ありは別に測定する。介入の行動数は記録し、想定表示時間には手番を使う通常行動のみを加える。

追加の集計は `averageDynamics`、`averageUnpaidFlameDebt`（`vowCompletionRate` は誓いの廃止とともに削除）。Markdownにも新機構の発生回数を出す。回避数は敵の予告が外れた回数、罠誘導数は可視の罠が敵へ実際に発動した回数であり、プレイヤーが意図して誘ったと断定する値ではない。既存の死亡原因・低命火・到達階・探索停滞・拾得・戦闘・階層移動・使用アイテム・実行時間も併せて見る。

探索停滞の連続カウンターは階層移動でリセットする。伝言数の集計は自動解決した判断も含める。探索済みの階段と未探索の境界を使って守り手を探し、隠れているボスの座標をAIへ渡さない。

## 保存と素材

campaign version 3を維持し、`lessons`・`flameDebt`・殉職者の`echoes`と`lesson`を省略可能な項目として追加した。既存の遠征団ID、古参、記録を保持する。旧墓標には残響がなくても弔いと遺品取得が機能する。

新規素材は透過PNGの2列2行 `public/assets/sprites/realtime-rites-sheet.png`。左上が置灯、右上が借灯、左下が殉職者の残響、右下が炉の通気口。生成方針は [素材の記録](sprite-refresh-prompts.md#リアルタイム遠征の素材2026-10-03)。危険範囲の色枠・残り手数・隙の輪は画像の代用ではなく、ゲーム情報を重ねる表示注釈。

音は追加していない。新しい敵・装備を増やすための変更も含めていない。

## 検証

`src/game/core/realtime.test.ts` で期限と通常行動、伝言中の攻撃、可視情報による回避、構えの中断、置灯と視界、借灯と返済、階層法則、墓標と教訓、誓い、台詞の再現性を確認する。標準test・TypeScript・build、複数seed×三職業のbatchとブラウザでの表示・操作を併用する。

ブラウザは1280×900と420×912で確認する。420×912はiPhone Airの表示寸法を模した検証で、実機Safariを操作した検証ではない。再現用の状態投入APIはdevビルドだけに置く。

### 2026-10-03の比較結果

30 seed `20260504:20260533` × 三職業、1600手、`temperament`、作戦なし、燭階0・余波なし、jobs 4。

| 条件 | 踏破 | 帰還 | 死亡 | 継続中 | 未帰還 | 平均想定表示時間 | 平均低命火手数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 旧config・介入なし | 28 | 28 | 34 | 0 | 0 | 4.23分 | 11.14 |
| 新config・介入なし | 40 | 27 | 21 | 2 | 0 | 4.40分 | 7.36 |
| 新config・灯守AI | 53 | 28 | 7 | 2 | 0 | 4.50分 | 5.11 |

新configの灯守AIは置灯55回・借灯8回。介入なしでも予告は一遠征平均25.72回、回避16.70回。最初の候補では平均表示時間が4.68分、双方踏破した同じ25遠征では旧5.30→新5.70分となった。回避や生存率だけでなく、戦闘以外の表示間隔も評価する必要があった。

そこで `pacingMs` を100/240/320/560から80/220/280/560msへ変更した。予告へ反応する戦闘時の時間を保ち、静かな移動と拾得を短縮する。調整前／後180遠征の結果・行動・低命火は同一で、平均表示時間は4.68→4.40分、双方踏破した同じ25遠征は旧5.30→新5.36分となった。実時間を短縮しても、灯火・予告・伝言の手数での寿命は変えない。

介入なしで1600手継続中の `20260510 / role.oathbound` と `20260523 / role.ash-scout` は、1800手の追加確認で1633手・1666手に踏破した。全seedを1800手で再測定した結果ではない。灯守AIで継続中だった2件も1600手の集計では踏破に含めていない。

旧／新の比較180遠征は26.21秒（6.87 runs/sec）、最終pacingの灯守AI90遠征は17.84秒（5.05 runs/sec）。これは今回のマシン・並列条件での壁時計で、性能改善率を示す値ではない。通常のJSONとMarkdownのレポートはGit管理外の `tmp/sim-reports/realtime-final.*`、`realtime-watcher-tempo.*`、pacing比較は `realtime-tempo.*`、延長確認は `realtime-limit.*`。

既知罠を踏む手は平均3.62→4.20、探索停滞手は51.12→59.62と増えている。可視の罠が敵へ発動する場面は標準90遠征で1回にとどまる。専用の狭路テストでは誘導から実際の敵被害まで確認したが、通常生成で頻繁に現れる仕組みとはしていない。この偏りも今後の候補config比較で確認する。
