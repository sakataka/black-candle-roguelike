# アビリティ（継承の心得）の設計

2026-10-05。継承品（職業ゆかりの装備を一つ持ち込む）を廃止し、遠征をまたいで集める常時効果「アビリティ」に置き換える。Hades の鏡やキープセイク、ドラゴンクエストの職業で覚えた特技を他の職でも使える仕組みを参考にした。

## 方針

- アビリティは常に効くパッシブだけにする。発動の判断がないので、探索者AIの判断を増やさず、人間とAIで同じ前提を保てる。
- 各職業の固有技（誓いの一撃、足止め射撃、聖なる光、看破、毒の瓶、突進、影渡り）はその職業だけのものとして残す。何でも使える状態にすると職業を選ぶ意味が薄れるため。
- 職業で踏破して得たアビリティは、その職業の特性を弱めた形にする。元の職業より強くしない。
- 組み合わせで遠征ごとの戦い方が変わることを狙う。重ねると強くなるが、枠には上限がある。

## 解放

アビリティは灰灯院の記録（campaign）から解放を判定する。一度解放すれば失わない。

| 条件 | アビリティ |
| --- | --- |
| その職業で初めて第十層を踏破する | 職業ごとに一つ（7種） |
| 黒燭への道の章を達成する | 第一の帰還路・真相を一つ・三つの真相・黒燭核・結末で一つずつ（5種） |
| 覚醒を突破する | 石・炉心・黒燭の覚醒で一つずつ（3種） |

職業の踏破は、従来の継承品と同じ `campaign.legacies`（第十層を踏破した職業ID）で記録する。保存形式は変えない。

## 枠と修練場

- 最初は2枠。施設「修練場」を強化するたびに1枠増え、最大6枠。
- 強化の費用は段ごとに大きく上げる（初期値 25 → 70 → 150 → 280 灯片）。最初の追加枠は1〜2回の遠征で手が届く費用にし、最後の枠は長く遊んだ先の目標にする。
- 付け外しは支度画面の「IV アビリティ」で行い、その遠征だけに効く。選んだ組み合わせは記録（campaign の `abilityLoadout`）に残し、次の支度でも引き継ぐ。解放していないものや枠を超える分は読み込み時に外す。

## 実装

- 効果は `abilities.definitions[id].effects` に持たせる。種類は、既存の職業特性と同じもの（`trapAvoidPercent`, `rangedDefense`, `healPercent`, `roomRevealRadius`, `stealth`, `bossReward`）と、新しく足したもの（`cleansingGuardTurns`, `attack`, `defense`, `maxHp`, `descentHeal`, `startEmbers`, `maxEmbers`, `bossDamagePercent`, `conditionDamageReduction`, `roomTrapReveal`, `freeUnlock`）。
- 遠征では `RunModifiers.abilities` に付けたアビリティのIDを持つ。`src/game/core/abilities.ts` の `playerTraits(state, actor)` が職業特性とアビリティの効果を合成し、これまで `roleTraits(contentId)` を読んでいた箇所の多くはこちらを読む。職業専用イベント（誓約の残響など）と固有技は職業IDで判定したまま変えない。
- 能力値（攻撃・防御・最大HP）は、鍛錬と同じく基礎値に足す。レベルアップで消えない。
- 灯火（出発時・上限）は、灯火の祭壇・燭階と同じ経路で足す。
- `GameObservation.modifiers` に含まれるので、AIは人間と同じ情報を見る。AIの判断閾値は変えない。

## 画面

- 支度画面「IV アビリティ」: 解放済みを選べるカードとして並べ、未解放は条件を見せて次の目標にする。枠の数を `2/3` のように出す。
- 出発の要約と観戦中の探索者欄に、付けているアビリティを出す。
- 結果画面: 新しく解放したアビリティを節目の碑で示す（従来の「継承品の解放」を置き換える）。
- 遊び方ガイドに「アビリティ」の説明と一覧を足す。
- アイコンは新しいスプライトシート（`public/assets/sprites/ability-icons-sheet.png`、4×4）。円形のメダリオンで作戦カードのアイコンと見分ける。最後のセルは修練場のアイコン。

## テストと調整の基盤

遠征の結果は、灰灯院の育ち具合（鍛錬、施設、アビリティ、覚醒、燭階）で大きく変わる。最初から遊ぶ場合と途中から遊ぶ場合を同じseed集合で比べられるよう、batchを広げる。

- `--abilities id,id`: 付けるアビリティを指定する。
- `--stage fresh|early|mid|late`: 灰灯院の育ち具合のプリセット（鍛錬・施設・アビリティ）。中身は `src/game/sim/scenarios.ts`。
- `--variant label=key:value,...`: 同じseed集合で条件だけを変えた列を並べる。`--config` と同じくレポートで横並びに比べられる。キーは `config`, `stage`, `abilities`（`+` 区切り）, `rank`, `trial`, `watcher`, `decision`, `heat`。
- `--ability-sweep`: アビリティなしの列と、各アビリティを一つだけ付けた列を自動で並べる。アビリティごとの効き目を比べる。

評価は従来の目安に加え、次を見る。

- 各アビリティ単体の踏破率の上げ幅。極端に強いもの・効かないものがないこと。
- `late`（6枠）でも通常遠征が楽勝になりすぎず、覚醒が壁として残ること。
- 職業ごとの差が、アビリティを付けても目安（全体の半分〜1.5倍）に収まること。

## 調整の記録（2026-10-05）

条件は `always-continue`、介入なし、100 seed `20260504:20260603` × 全7職（各700遠征）。アビリティなしの踏破は407/700（58%）。

### 一つだけ付けた時の上げ幅

| アビリティ | 初期案 | 調整後 |
| --- | ---: | ---: |
| 黒燭の心得 | +77 | 据え置き |
| 重装の心得 | +40 | 据え置き |
| 炉の心得 | +4 | +37（最大HP+8を追加） |
| 薬の知識 | +7 | +30（15%→25%） |
| 先人の力 | +25 | 据え置き |
| 黒燭の刃 | 30 seedで−4 | +24（15%→25%） |
| 石の心得 | +19 | 据え置き |
| 結末の残響 | 0 | +19（攻撃+1を追加） |
| 帰り道の知恵 | 30 seedで−4（回復6でも+3） | +16（回復4→12） |
| 忍び足 | 30 seedで−4 | +9（気配1→2、罠回避5→8%） |
| 鷹の目 | +6 | +8（罠回避10%・遠隔防御3） |
| 守り手の報い | +7 | 据え置き |
| 清めの加護 | +6 | +2（最大HP+4を追加） |
| 部屋読み | 0（半径3の地図は入れば見える範囲だった） | 罠を見抜く・道具なしで解錠に変更。差は揺れの範囲 |
| 真相の灯 | 0 | −7（最大HP+4を追加。揺れの範囲） |

- 灯火を増やす効果は、灯守AIありでも差が出なかった。灯守AIは灯火を余らせて溢れさせるため。人間が灯を使う遊び方で効く。
- 鷹の目・清めの加護・部屋読み・真相の灯は、勝率にはほとんど表れない。射手が多い遠征、毒が多い遠征、罠の多い寄り道、灯をよく使う遊び方で効く「状況向き」として残した。数ポイントの差を詰める調整はしない。

### 育ち具合ごとの踏破

| 条件 | 通常の遠征 | その時期の覚醒 |
| --- | ---: | ---: |
| fresh（鍛錬0・アビリティなし） | 407/700 | — |
| early（鍛錬2・2枠・祭壇1） | 501/700 | 第一の覚醒 197/700 |
| mid（鍛錬5・4枠・施設いくつか） | 606/700 | 第二の覚醒 225/700 |
| late（鍛錬10・6枠・施設最大） | 667/700 | 第三の覚醒 468/700 |

通常の遠征は成長につれて楽になり、各時期の覚醒は壁として残る。終盤でさらに難しさを求める場合は燭階を使う。

## batch の速さ

アビリティの組み合わせを比べるため、batchを速くした。結果は1ビットも変えていない（行動・観測・遠征録の指紋テストと、210遠征の全項目の突き合わせで確認）。

| 段階 | 標準batch（30 seed × 7職、1600手、jobs 8） |
| --- | ---: |
| 変更前 | 24.7秒 |
| 探索判定と経路探索を数値の格子にした | 16.7秒 |
| 観測の写しを共有し、線形探索を格子引きにした | 15.2秒 |
| 遠征ごとのプロセス起動をやめ、常駐ワーカーで流した | 7.2秒 |

一番効いたのは常駐ワーカーで、遠征ごとにプロセスを立て直すとJITが毎回冷えた状態から始まっていた（温まった状態では1遠征あたり約175ms）。言語を変える前に、TypeScriptのままでも計算の書き方と実行の仕方でまだ速くできる。
